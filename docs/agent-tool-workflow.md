# 有界财务 Agent：实现与验收

本轮增加模型驱动的原生工具调用。前端发送 `mode: "agent"`；不传 mode 保留 `workflow`，用于兼容旧客户端。`/agent/ask` 仍为旧 RAG 接口，新入口是 `POST /api/v1/ai/agent/chat/stream`。

## 执行方式

模型选择工具 → 后端校验参数与白名单 → 按服务端身份限定范围查询 → 结果返回模型 → 继续调用或结束。

四个只读工具：list_periods（可用月份）、query_metrics（确定性指标）、compare_expenses（按科目计算差额）、search_policies（可见制度）。季度参数用 `2026-Q3`，年度用 `2026`。不接受 SQL、用户身份或部门参数。费用比较先按全部科目算差额，再取增长最大的10项，总差额包含全部科目。

默认最多8次工具调用、9轮模型请求、90秒调度预算；每次模型请求最长30秒，禁用 SDK 自动重试；SQL statement_timeout 为10秒。时间预算在操作边界检查，不能硬中止正在运行的本地Embedding。停止也在模型返回和工具边界生效，不宣称立刻取消在途模型请求。

用量预算16000，结合模型上报用量和下一轮上下文字符数估算进行准入控制；单轮输出上限1200 tokens。这是应用预算，不是严格tokenizer计数或服务商账单。缺失 usage 时记录 usage_complete=false，不把部分用量显示为完整账单。Agent 检索禁用额外模型重排，避免隐藏模型调用。

年份不明确先检查是否为追问：仅在上轮解析状态的年份唯一且授权口径一致时继承，并保存期间、指标。两个年份比较后的“第二季度”仍请求澄清。新Agent不把历史回答作为本轮证据，每次重新查询。旧workflow模式保留原有历史消息预算。

缺失月份与可识别的查询超时只影响对应子任务，其他独立查询继续。最终分别展示通过检查的结论和未完成部分。两次参数错误终止任务，同工具同参数重复执行被拦截；未知执行异常仍终止任务。

工具结果分配本轮证据ID，财务工具同时返回规范化 facts。财务结论必须提供 fact_refs，逐项精确匹配 evidence_id、fact_id、metric、period、scope、value、unit；后端按匹配事实生成展示文字，不直接采用模型自由描述，避免正确引用夹带错误指标或原因。正确条目保留，不合格条目隐藏，全部不合格时允许一次修正。制度结论仍采用引用和数字检查；本机制不证明原始账目正确、制度语义正确或因果关系，仍需人工复核。

## 执行记录与界面

消息新增 JSONB execution_trace，启动时幂等迁移。工具执行前写入 tool_start，完成后写 tool；中断时可定位未完成步骤。模型用量、耗时、程序解析状态、校验结果和引用及时落库，不保存隐藏思考。记录读取沿用会话所有权校验。新增 evidence 展示快照：指标正文至多 6000 字、制度至多 5 个片段且每段 600 字、费用对比至多 10 项；片段为纯文本，可能截断，不代表完整原文。历史记录没有快照时只显示原有来源，不补造证据。

首页、预警列表和明细页可通过预警编号进入工作台。GET `/api/v1/ai/agent/alerts/{alert_id}/context` 核验当前账号权限并返回服务器记录的期间和部门；发送时附带 `alert_id`，后端再次核验并按预警自身范围执行工具，不接受 URL 中的部门覆盖。预填问题由用户发送，不在打开页面时自动调用模型。执行中展开步骤，完成后可折叠；重开预警会话时重新检查该预警是否仍然可见。

SSE 新增 progress、step，保留 start、delta、error、done。页面显示实际工具步骤，历史会话恢复步骤。模型工具选择采用非流式响应，最终文字经 SSE 分块展示；不是服务商逐 token 流式。收到消息编号后断线，前端最多自动进行三次只读查询，恢复已保存回答；仍在运行时提供手动查询和停止，禁止盲目重发。尚未收到编号时提示核对历史。后端锁定会话，拒绝同会话同时生成（409）。尚未实现事件游标续传、跨新会话全局幂等或进程重启后接续执行。

会话和消息保存结构化 scope_snapshot；列表在分页前按当前部门权限过滤，详情、续聊、消息恢复均复核权限。会话范围记录各轮范围并集；权限缩小后不能再访问超出当前范围的历史会话。受限账号不能读取缺少可信快照的旧记录，不从截断的展示标签推算权限。已发送到客户端的内容不能撤回，执行中的请求也不宣称实时撤权。

## 验证与复现

- `python -m pytest tests/test_agent_runner.py tests/test_api.py tests/test_knowledge_access.py tests/test_ai_retrieval.py`：执行循环、参数、权限、停止、预算、异常及接口落库回归。
- `npm test`（frontend）：会话、流读取取消、执行步骤和原有页面交互。
- `python scripts/evaluate_agent.py --live --compare`：10个合成任务，真实模型、PostgreSQL和Embedding，临时表隔离并回滚；同题运行原固定流程。支持 --case 和 --output 保留分次报告。
- `python scripts/check_pages.py --pages /agent --sizes 375x812 768x1000 1440x900 --inject-token`：三档尺寸检查与截图。

此前10项任务均通过当时的自动检查，新增复合缺失任务、连续追问、跨年澄清及负数冲销。该报告早于 fact_refs 字段绑定改造，不能作为新协议的真实模型验收结果。新协议由本地单元与接口回归验证，尚未重新调用外部模型。检查不等于语义准确率，全部回答仍需人工核验。

本轮报告：output/agent-evaluation-v2-final/report.md、results.json。原始首跑及单项复测保留在 agent-evaluation-v2 与 agent-evaluation-v2-followup 目录。首跑发现坏引用导致整段拦截，改成逐条检查；随后发现评测只接受“缺少”，把等义“没有以下月份的数据”误判失败，修正断言为允许两种缺失表述且要求partial状态，保留旧报告。

对照结果：简单收入查询A01，Agent约2031ms/3160 tokens，固定流程约1005ms/875 tokens；复合缺失任务A07，Agent保留2000元审批制度结论并提示缺失季度，固定流程遇到缺失直接结束。两种模式使用同模型、数据、问题和追问解析，但输出策略不同。这是单次合成案例，不是性能统计或生产准确率；不宣称Agent全面优于固定流程。失败时评测逐事件保存，异常前的步骤不会因list构造中断而丢失。

首轮发现季度格式说明不足、模型复述恶意文档中的标记；修正schema说明和提示。第二轮发现缺失被误说成权限不足，改成确定性提示。初次及第二次报告保留在 output/agent-evaluation/initial-results.json、second-results.json；最新报告为 results.json 和 report.md。A04的注入文档在用户可见范围内，确实进入了检索；单个案例不代表防注入完备。

## 面试演示与边界

选择有完整数据的期间，提问“对比2026年第二季度和第三季度费用，找出增长最多科目，并查询报销审批制度”。展示工具路径、后端计算的差额及引用，刷新后查看历史。随后演示缺失月份、未明确年份、越权请求和停止。

尚未实现：人工审批写操作、分布式任务恢复、多Agent、完整语义事实校验、服务商逐token输出及在途请求即时取消。不要将以上内容写成已完成。
