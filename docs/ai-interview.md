# AI 应用开发：项目介绍与验证边界

## 简历素材

智能财务分析平台（个人项目）｜Python、FastAPI、PostgreSQL/pgvector、Vue 3、SSE

- 实现财务数据导入、确定性指标计算与自然语言问答；后端提供指标、预警和明细作为模型证据，减少直接依赖模型计算产生的错误。
- 构建本地 Embedding 与 pgvector 检索链路，在数据库候选查询中限定部门可见范围，再进行可选的模型重排；重排失败回退向量排序。
- 实现 SSE 流式回答、停止请求、会话持久化和按预算裁剪的多轮上下文；区分服务商返回的 Token 用量与本地估算。
- 新增有界四工具Agent、独立子任务部分完成、同口径追问条件继承与基础证据检查；以10项合成任务对照固定流程的结果、耗时和用量，保留失败修复记录。Agent最终回答当前为完整生成后SSE分块，不宣称逐token输出。
- 将知识库上传、管理查询及删除按管理员身份和部门范围限制；公共资料必须由全公司管理员明确选择发布。
- 支持业务时区下的本月、上月、季度及明确月份区间；季度与年度由后端聚合，缺月则提示补充，避免生成不完整期间结论。
- 执行30题合成数据真实模型评测，保留题目、原始回答、检索来源、耗时和模型上报用量；数字检查与语义复核分别记录。

只写自己能解释、运行并展示的内容。个人贡献、开发时间由本人核对，不从代码行数或 Git 提交时间推断。

## 演示顺序

1. 展示一份已导入数据，说明数据来源及缺失字段。
2. 查询一个存在的月份，将回答金额与看板或明细核对。
3. 使用完整年月对比两期，例如“对比2026-01与2026-02的费用”，检查两期证据。
4. 查询一个不存在的月份，展示明确缺失提示，不调用生成模型。
5. 切换受限账号，说明财务查询及知识检索如何应用服务端权限。
6. 展示一次流式停止、历史会话及用量来源。

## 高频追问

- **这是自主 Agent 吗？** 前端默认使用有界工具调用Agent，模型动态选择四个只读工具，后端负责权限、参数和预算。旧固定工作流保留兼容；没有任意任务自治、多Agent或审批写入。细节见 [Agent实现与验收](agent-tool-workflow.md)。
- **可以杜绝幻觉吗？** 不可以。确定性计算约束数据来源，缺失月份由程序拦截，但生成文本仍需核验；尚无逐句事实验证器。
- **为什么权限前置？** 先取全库 Top K 再过滤可能被其他部门片段占满；权限进入 SQL WHERE 后，在可见集合内排序和截断。
- **重排一定更好吗？** 不保证。配置非空时使用指定的聊天兼容模型进行列表重排，不是专用 Cross Encoder 接口；准确率与延迟须用同一评测集对照。重排调用目前不纳入回答用量统计，不能把该统计当整条链路账单。
- **月份怎么解析？** 支持 YYYY-MM、YYYY/MM、YYYY年M月、2026-Q1、2026年第一季度、本月/上月、本季度/上季度、今年/去年，以及同粒度起止区间（最多24个月）。相对日期使用配置的业务时区；季度和年度缺月即提示。孤立的“3月”、同比/环比和复杂时间范围要求澄清，不能宣称任意时间表达均支持。
- **复杂财报解析支持到哪？** 当前 PDF 提取文本、DOCX 提取段落，按固定字符窗口切分。上传 PDF 尚未保留逐页定位，扫描件 OCR 和复杂表格解析尚未实现。
- **断线重连是什么程度？** 前端支持手动重试，不是携带事件游标的断点续传；重试可能新建一轮回答。
- **评测通过说明什么？** 离线回归验证程序行为；真实模型问答质量和真实 PostgreSQL 向量召回需要独立评测，不混为一个准确率。

## 验证方法

离线回归：`.venv/Scripts/python.exe scripts/test_ai_reliability.py`。不连接数据库、不访问模型；SDK 请求使用替身，SQL 检查采用 PostgreSQL 方言编译。

人工及真实模型评测见 [ai-evaluation.md](ai-evaluation.md)。不要将尚未执行的条目或仓库历史测量结果填写为本次通过。
